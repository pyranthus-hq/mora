# Ingest reference benchmarks

## Same-run regression gate (2026-09-29)

Run `bash scripts/regress/ingest-performance.sh` locally or in CI. The script
builds the pinned known-good main commit
`941ae612df6466f0cd9c3673d36da5c0604106c2` and the candidate with the same Go
toolchain on the same machine. It copies the candidate corpus benchmark harness
into the reference tree so both execute the same workload. No source checkout is
modified. The reference commit must be available locally (CI fetches full history).

For each 10K, 100K, and 1M corpus, the gate takes six paired reference/candidate
measurements, alternating their order so each binary runs first three times and
second three times. Each fresh benchmark process uses `-test.benchtime=3s`: Go
calibrates the iteration count separately for each corpus and binary to target
three seconds of measured work, with its normal warmup and GC behavior on both
sides. Ratios compare per-ingest `ns/op`, not total process runtime or iteration
counts. The median is the arithmetic mean of the two middle paired ratios.
The median candidate/reference ratio must be at most **1.20**. Missing reference
binaries, benchmark failures, and malformed measurements fail closed. Verbose
output records every pair for diagnosis.

A fixed commit, rather than the moving PR base, prevents cumulative slowdowns from
silently becoming the next baseline. Both binaries experience the current runner’s
speed, so a slower host does not itself consume the regression allowance. Paired
medians reduce transient load sensitivity; this is still a timing measurement and
sustained asymmetric load can affect it. The reference must only be changed after
reviewing the measured cost and any intentional behavior changes. Corpus changes
also require review because the same fixture is used on both sides.

The no-op ingest under two seconds and the 1,000-record allocation budget under
500 MiB remain independent gates. Total allocation is stricter than peak live heap
for that bounded run.

## Historical absolute measurements (not pass/fail thresholds)

Apple M1 Pro, darwin/arm64, Go benchmark `benchtime=1x`, captured 2026-08-24:

| Corpus | Median | Allocated bytes | Allocations |
|---:|---:|---:|---:|
| 10K | 9.27 ms | 5,323,368 | 89,800 |
| 100K | 53.08 ms | 53,243,024 | 900,222 |
| 1M | 530.48 ms | 532,425,368 | 9,004,268 |

The former hosted-runner profile was 11.86 ms, 96.33 ms, and 944.19 ms.
Independent branches with byte-identical ingest code crossed its 20% ceiling,
including a 1M median of 1.247 s. That profile was documented as
`macos-15-arm64`, while the workflow selected `macos-15`. Neither these historical
values nor a runner label is a substitute for a same-run control.

Raw benchmark command:

```bash
go test ./internal/memory -run '^$' -bench 'BenchmarkIngestCorpus(10K|100K|1M)$' -benchtime=3s -benchmem -count=6
```
