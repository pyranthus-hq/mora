# Mora Constitution

## Core Principles

1. Follow [AGENTS.md](../../AGENTS.md) for repository boundaries, Go
   compatibility, connector authority, storage, dependencies, and review.
2. Keep approved requirements and acceptance evidence traceable from feature
   specs to tasks and pull requests. Use the existing architecture docs to
   describe behavior after it ships.
3. Preserve Mora's local-first model, existing write policies, and the
   distinction between owner-authored content and agent evidence. A desktop
   surface uses the same vault and governance as existing Mora clients.
4. Verify the actual user workflow on each target platform. A build or
   mocked backend test does not establish desktop acceptance.

## Governance

Update this document only to reflect a repository-wide decision. Record
feature-specific choices in their own plans. Project rules remain in
`AGENTS.md`. Private feedback and release planning stay in the internal
product spec.
