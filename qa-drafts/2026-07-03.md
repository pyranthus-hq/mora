## Baseline defects reproduced this run (captured once, first ledger entry — not net-new)

### 1. `concurrency-index-loss` — P1 / concurrency / reliability

**Summary:** 25 concurrent `mora write` calls to the same scope all succeed and land 25 `.md` files on disk, but the FTS index only picks up 19 of them.

**Repro:**
```bash
export HOME=/tmp/moraqa
for i in $(seq 1 25); do
  /tmp/mora write --scope project:concur --title "Concurrent Item $i" \
    --text "CONCURTOKEN item number $i" --json > /tmp/concur_$i.log 2>&1 &
done
wait
find /tmp/moraqa/vault/memories/project/concur -name '*.md' | wc -l   # -> 25
/tmp/mora search CONCURTOKEN --limit 40 --json | grep -c '"id"'       # -> 19
/tmp/mora index rebuild                                               # "indexed 25 memories"
/tmp/mora search CONCURTOKEN --limit 40 --json | grep -c '"id"'       # -> 25 (fixed only after rebuild)
```
**Expected:** search-visible count == files-on-disk count without a manual rebuild.
**Actual:** 6/25 writes (24%) silently invisible to search until `index rebuild` is run.
**Impact:** An agent writing memories concurrently (e.g. parallel subagents journaling) will lose recall on ~1 in 4 items with no error surfaced anywhere.

### 2. `scope-path-traversal` — P1 / security

**Summary:** `--scope '../../escaped'` is not sanitized and writes a file outside the vault root.

**Repro:**
```bash
export HOME=/tmp/moraqa
/tmp/mora write --scope '../../escaped' --title "Escape Test" --text "ESCAPETOKEN" --json
# "path": "/tmp/moraqa/escaped/mem_....md"  <- outside /tmp/moraqa/vault entirely
```
**Expected:** scope path components should be sanitized/rejected so all writes stay under the vault root.
**Actual:** the file lands two directories above the vault (`$HOME/escaped/...`), exit 0, no warning.
**Impact:** arbitrary-ish file write outside the vault via a single flag; especially bad if `mora` ever runs with elevated permissions or the scope value is agent/LLM-controlled.

### 3. `tasks-list-returns-done` — P2 / reliability

**Summary:** `mora tasks list --json` still returns tasks with `"status":"done"` in the default (non-filtered) listing.

**Repro:**
```bash
export HOME=/tmp/moraqa
/tmp/mora tasks add "QA Test Task"
/tmp/mora tasks done "QA Test Task"
/tmp/mora tasks list --json
# [{"task":"QA Test Task", ..., "status":"done", ...}]
```
**Expected:** default `tasks list` shows only live/queued tasks (done tasks need an explicit `--all`/`--done` opt-in, or the design doc should state otherwise).
**Actual:** done tasks stay in the default list indefinitely, polluting an agent's live-task view.

### 4. `no-write-dedup` — P3 / dx

**Summary:** Writing identical title+text twice to the same scope creates two separate memories, no content-hash/dedup check.

**Repro:**
```bash
/tmp/mora write --scope project:dedup --title "Dup Test" --text "DEDUPTOKEN same content twice" --json
/tmp/mora write --scope project:dedup --title "Dup Test" --text "DEDUPTOKEN same content twice" --json
/tmp/mora search DEDUPTOKEN --limit 10 --json | grep -c '"id"'   # -> 2
```
**Impact:** agents retrying a write after a timeout/ambiguous response will silently duplicate memories, degrading search quality over time.

### 5. `dx-help-and-validation` — P2 / dx

**Summary:** `--help` handling is inconsistent and in one case actively harmful.

**Repro / evidence:**
```bash
/tmp/mora init --help     # -> "flag: help requested", exit 1  (raw Go flag-package leak)
/tmp/mora write --help    # -> "flag: help requested", exit 1
/tmp/mora context --help  # -> "flag: help requested", exit 1
/tmp/mora delete --help   # -> "flag: help requested", exit 1
/tmp/mora search --help   # -> proper "usage: mora search <query> [--scope S] [--limit N] [--json]", exit 0
/tmp/mora tasks --help    # -> proper usage line, exit 0
/tmp/mora think --help    # -> treats "--help" as the literal query text and RUNS A REAL SEARCH:
                           #    "Q: --help\n\nEvidence (0): ...", exit 0
```
**Expected:** every subcommand prints usage text and exits 0 on `--help`.
**Actual:** 4/7 commands leak the raw Go `flag` package error and exit 1; `mora think --help` is worst of all — it doesn't recognize `--help` and instead executes a live (empty) query against the vault, which is exactly the "runs a real query" failure mode called out for this check.
**Impact:** breaks scripted/agent discovery of CLI usage (`--help` is commonly probed programmatically); `think --help` wasting a query cycle is a footgun for agents introspecting the tool.
