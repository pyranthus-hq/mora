## NET-NEW: `tasks add --help` silently writes a literal task instead of showing help

**Labels:** bug, dx, P2

**Summary:** Unlike the read-only `--help` mishandling already tracked under
`dx-help-and-validation` (where `mora think --help` runs a real, harmless
query), `mora tasks add --help` performs a **write**: it persists a literal
task row named `--help` into `live-tasks.md` and reports success, with no
help text ever shown.

**Impact:** For an agent driving Mora non-interactively, a `--help` probe
(a common first move to discover flags) silently corrupts the live task
list with junk data instead of failing loudly or printing usage. For a solo
founder skimming `mora tasks list`, a stray `--help` P1 task appears
indistinguishable from a real captured task, adding noise to exactly the
list that's supposed to be a trustworthy source of open loops.

**Reproduction:**
```
export HOME=/tmp/moraqa
/tmp/mora tasks add --help
# → "task added: --help"  (exit 0)
/tmp/mora tasks list --json
# → includes {"task":"--help","domain":"memory","owner":"you","pri":"P1","status":"queued",...}
```

**Expected:** `--help` (or `-h`) as the first token after `tasks add` should
print usage and exit without mutating `live-tasks.md`, matching the
documented usage string (`mora tasks add <name> [--pri P1] ...`).

**Actual:** The literal string `--help` becomes the task name; `addTask`
persists it and the command exits 0.

**Suggested fix:** In `cmdTasks`'s `"add"` case (`internal/mora/mora.go`,
around line 1279, right after `name := strings.TrimSpace(args[1])`), check
`name == "-h" || name == "--help"` and print usage instead of falling
through to `addTask`. The same guard is worth applying to any other
name-first subcommand (e.g. `tasks done`) for consistency — this run only
reproduced it for `tasks add`.

**Environment:** `mora dev` (commit `db3958f`), go1.25.8 linux/amd64,
Linux 6.18.5, sandbox vault at `/tmp/moraqa/vault`.

- **`concurrency-index-loss`** — 25 concurrent `mora write` to one scope
  produced 25 files on disk but only **2** were returned by
  `mora search TOKEN --limit 40 --json`. `mora index rebuild` then reported
  "indexed 25 memories" and the count corrected to 25/25. Still present,
  unchanged severity.
- **`scope-path-traversal`** — `mora write --scope '../../escaped' --title E --text X`
  wrote to `/tmp/moraqa/escaped/mem_....md`, one level **outside** the vault
  root (`/tmp/moraqa/vault`). Still present, unchanged severity.
- **`dx-help-and-validation`** — `mora write --help`, `mora context --help`,
  and `mora init --help` all print the bare Go flag error
  `flag: help requested` and exit 1 (no usage text). `mora think --help`
  instead treats `--help` as a literal query string and runs a real
  (empty-result) query against the vault, exit 0. Still present, unchanged.
- **`tasks-list-returns-done`** — `mora tasks list --json` includes
  completed tasks (with `"status":"done"`) in the same array as live ones,
  rather than a live-only list by default. Still present, unchanged.
- **`no-write-dedup`** — writing identical `--title`/`--text` twice produces
  two distinct memory ids; both are returned by search. Still present,
  unchanged.
